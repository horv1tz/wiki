# Участие в вики

## Как добавить статью

1. Создайте файл в соответствующем разделе: `devops/`, `linux/`, `monitoring/`, `vcs/`, `web/`, `windows/`, `artifacts/`, `database/`
2. Имя файла — транслитом в kebab-case, например `ustanovka-i-nastroika-gitlab-ee.md`
3. Оформите статью по шаблону ниже
4. Добавьте ссылку в `SUMMARY.md` (навигация GitBook) и `README.md` (оглавление с описанием)

## Шаблон статьи

```markdown
---
description: Краткое описание статьи (показывается в поиске и превью)
---

# Название

Вводный абзац: что это за инструмент и для чего нужен.

## 1. Первый раздел

### 1.1 Подраздел

Текст с примерами.

​```bash
# команды в блоках кода с указанием языка
sudo apt install <пакет>
​```

> **Важно:** замечания и предупреждения — в цитатах.

## Полезные ссылки

* [Официальная документация](https://example.com)
```

## Правила оформления

* Язык — русский; технические термины (executor, playbook, pipeline) можно оставлять как есть
* Команды — только актуальные: `docker compose` (не `docker-compose`), `dnf` (не `yum`), `git switch` (не `git checkout` для веток)
* Версии в примерах — с указанием, что нужно проверить актуальную
* Не помещайте в статьи реальные пароли, токены и ключи — только плейсхолдеры `<пароль>`
* Перед публикацией проверьте, что команды рабочие: скопируйте и выполните на тестовой машине

## Проверки

CI автоматически проверяет markdown (markdownlint), ссылки (lychee) и орфографию (yaspeller). Локально:

```bash
npx markdownlint-cli2 "**/*.md"
npx yaspeller --config .yaspellerrc .
```
